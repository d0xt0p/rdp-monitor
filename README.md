# RDP Monitor

Небольшой монитор RDP-подключения Remmina для **ALT Linux**: Bash выполняет проверки, Tcl/Tk показывает состояние и позволяет управлять монитором. Python для работы приложения не нужен.

## Возможности

- Обнаружение TCP-соединения Remmina на порту 3389 через `ss`.
- Звуковая тревога после потери ранее обнаруженного соединения: пять неудачных проверок с интервалом две секунды (примерно десять секунд).
- Отключение звука на одну минуту и автоматическое прекращение тревоги при восстановлении соединения.
- Графический интерфейс с обновлением состояния раз в две секунды.
- Проверка VPN-интерфейса (по умолчанию `tun0`): флаги `UP`, `LOWER_UP` и наличие IPv4-адреса.
- Фоновая проверка доступа к интернету примерно раз в 15 секунд: Cloudflare, затем `ya.ru` при неудаче.
- Проверка параметра `keyboard_grab` в профилях Remmina, его исправление по отдельной команде и запуск Remmina.

## Требования

Нужны уже установленные Bash 4.4+, Tcl/Tk (`wish`), Remmina, `ss`, `ip`, `flock`, стандартные GNU-утилиты и `paplay` для звука. Для проверки интернета нужен `curl` или `wget`. Программа рассчитана на графический сеанс пользователя Linux и не требует root-прав.

Проверить наличие команд:

```bash
for cmd in bash wish remmina ss ip flock paplay curl wget; do
    command -v "$cmd" || true
done
```

Приложение ничего не устанавливает. Если какой-либо зависимости нет, её установка — отдельное действие, которое может потребовать администратора.

## Установка и запуск

Скачайте архив из [Releases](https://github.com/d0xt0p/rdp-monitor/releases), распакуйте и скопируйте каталог в доступное для записи место, например `~/bin/rdp-monitor`. Оба скрипта должны находиться рядом.

```bash
cd ~/bin/rdp-monitor
chmod +x rdp-monitor.sh rdp-monitor-gui.tcl
./rdp-monitor.sh autostart
```

Для звуковой тревоги поместите собственный `alert.mp3` рядом со скриптами. Файл из рабочей установки не распространяется: его происхождение и права на распространение не подтверждены. Поддержка MP3 зависит от возможностей `paplay` в системе. Обязательно проверьте звук отдельно:

```bash
paplay ./alert.mp3
```

Можно использовать другой поддерживаемый звуковой файл, например WAV, задав абсолютный путь:

```bash
export RDP_MONITOR_ALERT_FILE="$HOME/Music/alert.wav"
export RDP_MONITOR_VPN_INTERFACE="tun0"
./rdp-monitor.sh autostart
```

Переменные должны быть заданы до запуска монитора и GUI. После изменения настроек перезапустите оба процесса. Пути с пробелами допустимы.

## Команды

| Команда | Действие |
| --- | --- |
| `./rdp-monitor.sh autostart` | Запустить монитор и GUI |
| `./rdp-monitor.sh start` | Запустить монитор в фоне |
| `./rdp-monitor.sh stop` | Остановить монитор и тревогу |
| `./rdp-monitor.sh status` | Показать текущее и сохранённое состояние |
| `./rdp-monitor.sh gui` | Открыть GUI |
| `./rdp-monitor.sh snooze` | Отложить тревогу на минуту |
| `./rdp-monitor.sh network-refresh` | Однократно обновить проверки сети |
| `./rdp-monitor.sh remmina-check` | Проверить профили Remmina |
| `./rdp-monitor.sh remmina-fix` | Установить `keyboard_grab=1` во всех найденных профилях |
| `./rdp-monitor.sh remmina-launch` | Запустить Remmina |

Кнопка **«Выход»** закрывает GUI, фоновый монитор продолжает работу. Для его остановки используйте **«Остановить»** или команду `stop`. Команда `monitor` предназначена для запуска основного цикла на переднем плане.

`remmina-fix` изменяет все файлы `*.remmina` в `${XDG_DATA_HOME:-$HOME/.local/share}/remmina`, включая подпапки. Перед изменением каждого файла создаётся `.bak`; повторный запуск перезаписывает эту копию. Сохраните отдельную резервную копию профилей, если требуется более ранняя конфигурация. Команда не завершает Remmina: перезапустите её самостоятельно после исправления. Проверка профилей возвращает ненулевой код, если есть профили без `keyboard_grab=1` или профилей нет.

## Ограничения

- Обнаруживается первое установленное TCP-соединение процесса Remmina на порту 3389. Другие порты, SSH-пробросы, только UDP и несколько одновременных сеансов требуют доработки.
- Наличие TCP-соединения не подтверждает отзывчивость удалённого рабочего стола; состояние `tun0` не подтверждает доступность удалённых ресурсов через VPN.
- Тревога включается только после того, как монитор хотя бы один раз увидел соединение. Запуск без RDP не вызывает тревогу.
- Проверка интернета подтверждает возможность выполнить запрос к одному из двух сайтов. Это не проверка всех маршрутов и не оценка HTTP-кода ответа. HTTPS-сертификаты проверяются системными средствами.
- Сетевой кэш обновляется автоматически, пока открыт GUI. При работе только в фоне вызовите `network-refresh` отдельно.
- `UPDATED` в файле состояния — время последней записи события, а не постоянный сигнал активности.
- Звук и полноценная работа GUI должны быть проверены в целевом ALT Linux. Без доступного аудиофайла звуковой сигнал не гарантируется.

## Файлы и конфиденциальность

Скрипты создают рядом с собой PID-файлы, блокировки, состояние и сетевой кэш. Эти файлы могут содержать адрес удалённого узла и адрес VPN-интерфейса. Они исключены из Git и не входят в релиз. Не публикуйте содержимое рабочего каталога целиком, профили Remmina и снимки экрана с рабочими адресами.

Новые служебные файлы создаются с ограниченными правами (`umask 077`). При обновлении существующей установки проверьте также права ранее созданных файлов. Не запускайте монитор от root и не используйте общий каталог, доступный другим пользователям на запись.
